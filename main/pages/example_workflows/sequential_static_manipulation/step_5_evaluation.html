Closed-Loop Policy Inference and Evaluation#

This workflow demonstrates running the trained GR00T N1.6 policy in closed-loop and evaluating it in the GR1 Sequential Pick & Place and Close Door Environment.

Prepare the Arena runtime from the repository root, using either a native uv environment or the base Docker container (see Installation for the full setup):

uv sync --extra dev --group gr00t-client
source .venv/bin/activate
export OMNI_KIT_ACCEPT_EULA=YES ACCEPT_EULA=Y

./docker/run_docker.sh

Once the runtime is ready, set the dataset and models directories.

export DATASET_DIR="$HOME/datasets/isaaclab_arena/sequential_static_manipulation_tutorial"
export MODELS_DIR="$HOME/models/isaaclab_arena/sequential_static_manipulation_tutorial"

Note that this tutorial assumes that you’ve completed the preceding step (Policy Training) or downloaded the pre-trained model checkpoint below:

Download Pre-trained Model (skip preceding steps)

These commands can be used to download the pre-trained GR00T N1.6 policy checkpoint, such that the preceding steps can be skipped.

mkdir -p $MODELS_DIR/checkpoint-20000
hf download \
  nvidia/GN1.6-Tuned-Arena-GR1-PlaceItemCloseDoor-Task \
  --include "ranch_bottle_into_fridge/*" \
  --repo-type model \
  --local-dir $MODELS_DIR/_hf_download
mv $MODELS_DIR/_hf_download/ranch_bottle_into_fridge/* $MODELS_DIR/checkpoint-20000/
rm -rf $MODELS_DIR/_hf_download

Prerequisite: launch the GR00T policy server

The Arena evaluation client runs in the Arena runtime and connects to a GR00T policy server. Before running the evaluation, open another terminal, separate from the Arena runtime, for the server. The server runs out of the Isaac-GR00T source submodule pinned at commit e29d8fc; populate it with git submodule update --init submodules/Isaac-GR00T if it is not already checked out. Then, from the repository root in that terminal, launch the server and leave it running:

Note

Blackwell GPUs with compute capability sm_120 require CUDA 12.8 or newer. The GR00T environment setup guide specifies CUDA 12.8 and pytorch-cu128 for RTX 5090 systems.

cd submodules/Isaac-GR00T
uv run python gr00t/eval/run_gr00t_server.py \
  --modality-config-path ../../isaaclab_arena_policies/isaaclab_arena_gr00t/embodiments/gr1/gr1_arms_only_data_config.py \
  --model-path $HOME/models/isaaclab_arena/sequential_static_manipulation_tutorial/checkpoint-20000 \
  --embodiment-tag GR1 \
  --device cuda --host 127.0.0.1 --port 5555

If you trained with the Low Hardware Requirements option in Policy Post-training, pass checkpoint-30000 to --model-path instead. That training also keeps checkpoint-20000, which is only two thirds of the way through training.

Step 1: Run Single Environment Evaluation#

We first run the policy in a single environment with visualization via the GUI.

The Arena GR00T evaluation client is configured by a config file at isaaclab_arena_policies/isaaclab_arena_gr00t/policy/config/gr1_manip_ranch_bottle_gr00t_closedloop_config.yaml.

Configuration file (gr1_manip_ranch_bottle_gr00t_closedloop_config.yaml):
language_instruction: "Place the sauce bottle on the top shelf of the fridge, and close the fridge door."
action_horizon: 16
video_backend: decord
modality_config_path: isaaclab_arena_policies/isaaclab_arena_gr00t/embodiments/gr1/gr1_arms_only_data_config.py

action_chunk_length: 16
gr00t_embodiment_adapter: gr1_arms

pov_cam_name_sim: "robot_pov_cam_rgb"

original_image_size: [512, 512, 3]
target_image_size: [512, 512, 3]

The evaluation itself is an Arena Experiment with one Run. It selects the environment, the gr1_joint embodiment and the ranch dressing bottle, loads the GR00T client config above, connects the client to the server, and stops after 2000 steps.

Experiment file (gr1_put_ranch_bottle_in_fridge_gr00t_experiment.yaml):
# Evaluate the GR00T policy from the sequential static manipulation workflow on the ranch dressing
# bottle it was trained on, in one environment for 2000 steps.
# To evaluate 10 parallel environments, add this override to the experiment_runner.py command:
#   runs.gr1_put_ranch_bottle_in_fridge_and_close_door.environment_builder.num_envs=10
runs:
  gr1_put_ranch_bottle_in_fridge_and_close_door:
    environment:
      type: put_item_in_fridge_and_close_door
      enable_cameras: true
      embodiment: gr1_joint
      object: ranch_dressing_hope_robolab
    policy:
      type: isaaclab_arena_gr00t.policy.gr00t_remote_closedloop_policy.Gr00tRemoteClosedloopPolicy
      policy_config_yaml_path: isaaclab_arena_policies/isaaclab_arena_gr00t/policy/config/gr1_manip_ranch_bottle_gr00t_closedloop_config.yaml
      policy_device: cuda:0
      remote_host: 127.0.0.1
      remote_port: 5555
    rollout_limit:
      num_steps: 2000

Test the policy in a single environment with visualization via the GUI run:

python isaaclab_arena/evaluation/experiment_runner.py \
  --viz kit \
  --experiment_config isaaclab_arena_environments/experiment_configs/gr1_put_ranch_bottle_in_fridge_gr00t_experiment.yaml

At the end of the evaluation, the console shows the Run table with the number of recorded episodes, the success rate, and the success rate of each subtask: placing the bottle, then closing the door. With the pre-trained checkpoint, the output looks like this:

+-----------------------------------------------+-----------+-------------------------+----------+-----------+--------------+--------------+-------------------+--------------+-----------------------+
|                    Run Name                   |   Status  |       Policy Type       | Num Envs | Num Steps | Num Episodes | Num Rebuilds | Recorded Episodes | Success Rate | Subtask Success Rates |
+-----------------------------------------------+-----------+-------------------------+----------+-----------+--------------+--------------+-------------------+--------------+-----------------------+
| gr1_put_ranch_bottle_in_fridge_and_close_door | completed | gr00t_remote_closedloop |    1     |    2000   |     None     |      1       |         5         |    0.8000    |     0.8000, 0.8000    |
+-----------------------------------------------+-----------+-------------------------+----------+-----------+--------------+--------------+-------------------+--------------+-----------------------+

The rates cover all episodes that finish within the 2000 steps. They depend on the quality of the post-trained policy, the quality of the dataset, and the number of steps in the evaluation, and they vary between evaluations, especially with few episodes.

Step 2: Run Parallel environments Evaluation#

The same Experiment can evaluate the policy in several parallel environments. Set the number of environments on the command line instead of editing the file: runs.<Run name>.<field>=<value> changes one field of that Run.

Test the policy in 10 parallel environments with visualization via the GUI run:

python isaaclab_arena/evaluation/experiment_runner.py \
  --viz kit \
  --experiment_config isaaclab_arena_environments/experiment_configs/gr1_put_ranch_bottle_in_fridge_gr00t_experiment.yaml \
  runs.gr1_put_ranch_bottle_in_fridge_and_close_door.environment_builder.num_envs=10

During the evaluation, the console shows which environments reset because their episode ended, for example because the task finished or the episode ran out of time:

Resetting policy state for env_ids: tensor([5], device='cuda:0')

At the end of the evaluation, the console shows the Run table. With 10 environments, the same number of steps covers about ten times as many episodes as the single environment evaluation, so the success rate is a more reliable estimate.

+-----------------------------------------------+-----------+-------------------------+----------+-----------+--------------+--------------+-------------------+--------------+-----------------------+
|                    Run Name                   |   Status  |       Policy Type       | Num Envs | Num Steps | Num Episodes | Num Rebuilds | Recorded Episodes | Success Rate | Subtask Success Rates |
+-----------------------------------------------+-----------+-------------------------+----------+-----------+--------------+--------------+-------------------+--------------+-----------------------+
| gr1_put_ranch_bottle_in_fridge_and_close_door | completed | gr00t_remote_closedloop |    10    |    2000   |     None     |      1       |         46        |    0.8261    |     0.8261, 0.8261    |
+-----------------------------------------------+-----------+-------------------------+----------+-----------+--------------+--------------+-------------------+--------------+-----------------------+

Note

Note that the embodiment used in closed-loop policy inference is gr1_joint, which is different from gr1_pink used in data generation. This is because during tele-operation, the robot is controlled via target end-effector poses, which are realized by using the PINK IK controller. GR00T N1.6 policy is trained on upper body joint positions, so we use gr1_joint for closed-loop policy inference.

Step 3: Evaluate on Several Sauce Bottles#

This step evaluates the same policy on four sauce bottles: ketchup, ranch dressing, barbecue sauce and mayonnaise. The asset selection variation makes the Run build the scene once per bottle, in list order. All 10 parallel environments of a build use the same bottle, and each build runs 10 of the 40 episodes.

The variation belongs to the object that the robot puts in the fridge. That object keeps the name ranch_dressing_hope_robolab from environment.object, while the variation replaces its asset with each listed bottle in turn.

Experiment file (gr1_put_sauce_bottles_in_fridge_gr00t_experiment.yaml):
# Evaluate the GR00T policy from the sequential static manipulation workflow on four sauce bottles.
# Asset selection builds the scene once per bottle, in list order, with the same bottle in all
# 10 parallel environments. Each build runs 10 of the 40 episodes. The variation belongs to the
# object named ranch_dressing_hope_robolab after environment.object and replaces its asset.
runs:
  gr1_put_sauce_bottles_in_fridge_and_close_door:
    environment:
      type: put_item_in_fridge_and_close_door
      enable_cameras: true
      embodiment: gr1_joint
      object: ranch_dressing_hope_robolab
    environment_builder:
      num_envs: 10
    policy:
      type: isaaclab_arena_gr00t.policy.gr00t_remote_closedloop_policy.Gr00tRemoteClosedloopPolicy
      policy_config_yaml_path: isaaclab_arena_policies/isaaclab_arena_gr00t/policy/config/gr1_manip_ranch_bottle_gr00t_closedloop_config.yaml
      policy_device: cuda:0
      remote_host: 127.0.0.1
      remote_port: 5555
    num_rebuilds: 4
    rollout_limit:
      num_episodes: 40
    variations:
      ranch_dressing_hope_robolab.asset_selection.enabled: true
      ranch_dressing_hope_robolab.asset_selection.registry_names:
        [ketchup_bottle_hope_robolab, ranch_dressing_hope_robolab, bbq_sauce_bottle_hope_robolab, mayonnaise_bottle_hope_robolab]

Test the policy in 10 parallel environments with visualization via the GUI run:

python isaaclab_arena/evaluation/experiment_runner.py \
  --viz kit \
  --experiment_config isaaclab_arena_environments/experiment_configs/gr1_put_sauce_bottles_in_fridge_gr00t_experiment.yaml

At the end of the evaluation, the console shows the Run table over all 40 episodes, followed by the success rate for each bottle:

+------------------------------------------------+-----------+-------------------------+----------+-----------+--------------+--------------+-------------------+--------------+-----------------------+
|                    Run Name                    |   Status  |       Policy Type       | Num Envs | Num Steps | Num Episodes | Num Rebuilds | Recorded Episodes | Success Rate | Subtask Success Rates |
+------------------------------------------------+-----------+-------------------------+----------+-----------+--------------+--------------+-------------------+--------------+-----------------------+
| gr1_put_sauce_bottles_in_fridge_and_close_door | completed | gr00t_remote_closedloop |    10    |    None   |      40      |      4       |         40        |    0.6000    |     0.7000, 0.7000    |
+------------------------------------------------+-----------+-------------------------+----------+-----------+--------------+--------------+-------------------+--------------+-----------------------+
+------------------------------------------------+---------------------------------------------+----------------------------------+----------+-----------+---------+--------------+
|                      Run                       |                  Variation                  |              Value               | Episodes | Successes | Unknown | Success Rate |
+------------------------------------------------+---------------------------------------------+----------------------------------+----------+-----------+---------+--------------+
| gr1_put_sauce_bottles_in_fridge_and_close_door | ranch_dressing_hope_robolab.asset_selection | "bbq_sauce_bottle_hope_robolab"  |    10    |     5     |    0    |    50.0%     |
| gr1_put_sauce_bottles_in_fridge_and_close_door | ranch_dressing_hope_robolab.asset_selection |  "ketchup_bottle_hope_robolab"   |    10    |     6     |    0    |    60.0%     |
| gr1_put_sauce_bottles_in_fridge_and_close_door | ranch_dressing_hope_robolab.asset_selection | "mayonnaise_bottle_hope_robolab" |    10    |     5     |    0    |    50.0%     |
| gr1_put_sauce_bottles_in_fridge_and_close_door | ranch_dressing_hope_robolab.asset_selection |  "ranch_dressing_hope_robolab"   |    10    |     8     |    0    |    80.0%     |

The policy was trained only on the ranch dressing bottle and succeeds with it in 8 of 10 episodes. On each of the other three bottles it succeeds in 5 or 6 of 10 episodes, so it partly transfers to bottles it has not seen.

Step 4: Sequential Batch Evaluation#

An Experiment can also hold several Runs. experiment_runner.py evaluates them one after another in the same simulation application, and each Run reports its own success rate. The Experiment below evaluates the policy on an unseen jug and on the ranch dressing bottle as two Runs.

Experiment file (gr1_sequential_static_manip_gr00t_experiment.yaml):
# Evaluate the GR00T policy from the sequential static manipulation workflow on an unseen jug and
# on the ranch dressing bottle it was trained on. Both Runs use the language instruction from the
# policy config, so only the object differs.
shared:
  environment:
    type: put_item_in_fridge_and_close_door
    enable_cameras: true
    embodiment: gr1_joint
  environment_builder:
    num_envs: 10
  policy:
    type: isaaclab_arena_gr00t.policy.gr00t_remote_closedloop_policy.Gr00tRemoteClosedloopPolicy
    policy_config_yaml_path: isaaclab_arena_policies/isaaclab_arena_gr00t/policy/config/gr1_manip_ranch_bottle_gr00t_closedloop_config.yaml
    policy_device: cuda:0
    remote_host: 127.0.0.1
    remote_port: 5555
  rollout_limit:
    num_steps: 500

runs:
  gr1_put_jug_in_fridge_and_close_door:
    environment:
      object: jug

  gr1_put_ranch_dressing_bottle_in_fridge_and_close_door:
    environment:
      object: ranch_dressing_hope_robolab

Run the batch evaluation:

python isaaclab_arena/evaluation/experiment_runner.py \
  --viz kit \
  --experiment_config isaaclab_arena_environments/experiment_configs/gr1_sequential_static_manip_gr00t_experiment.yaml

This will automatically evaluate the policy with the given configuration. You should see the following output on the console with the runs and their success rates.

+--------------------------------------------------------+-----------+-------------------------+----------+-----------+--------------+--------------+-------------------+--------------+-----------------------+
|                        Run Name                        |   Status  |       Policy Type       | Num Envs | Num Steps | Num Episodes | Num Rebuilds | Recorded Episodes | Success Rate | Subtask Success Rates |
+--------------------------------------------------------+-----------+-------------------------+----------+-----------+--------------+--------------+-------------------+--------------+-----------------------+
|          gr1_put_jug_in_fridge_and_close_door          | completed | gr00t_remote_closedloop |    10    |    500    |     None     |      1       |         10        |    0.1000    |     0.2000, 0.2000    |
| gr1_put_ranch_dressing_bottle_in_fridge_and_close_door | completed | gr00t_remote_closedloop |    10    |    500    |     None     |      1       |         10        |    0.9000    |     0.9000, 0.9000    |
+--------------------------------------------------------+-----------+-------------------------+----------+-----------+--------------+--------------+-------------------+--------------+-----------------------+

Subtask Success Rates lists each subtask’s success rate in order: placing the object, then closing the door. In a sequential task a subtask only counts once the ones before it are complete. This task also requires both subtasks to still hold when the episode ends, so its success rate can be lower than the subtask rates.

With the policy trained on using ranch dressing bottle as object of interest, the success rate for generalizing to putting the unseen object, jug, in the fridge is 0.1. This is expected as the policy is not trained on the jug, comparing to the success rate of 0.9 for the trained object, ranch dressing bottle.
