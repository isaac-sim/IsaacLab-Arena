Relations Reference
===================

Every relation an environment graph YAML can use, generated from the relation classes in
``isaaclab_arena/relations/relations.py``. ``kind`` is the name in a YAML ``relations`` entry.
A binary relation takes a ``reference`` object; a unary one does not. Constructor arguments go
under ``params``. The validation check is the pre-physics check that rejects layouts breaking
the relation; a relation without one is only a solver objective, so valid layouts can miss it
slightly. Every layout is also checked for overlaps by ``no_overlap``. For how to combine
relations, see :doc:`relations`.

.. _relation-align_with:

``align_with`` (AlignWith)
--------------------------

Aligns the subject's placement-box centre with the reference's along one world axis.

The subject's centre is placed at the reference's centre plus ``offset_m`` along ``axis``; the
other axes stay free. Combine it with NextTo to set a gap on one horizontal axis and alignment on
the other, or use two AlignWith relations for a target region relative to the reference's centre.

**Validation:** the ``align_with`` check rejects layouts whose centre error along ``axis`` exceeds
``tolerance_m``.

**Restrictions:** the subject cannot be an anchor, and the reference must be a different object that
takes part in placement. Horizontal alignment cannot use an object that FaceTo turns if that
object's placement bounds are off-centre; see FaceTo.

.. list-table::
   :header-rows: 1
   :widths: 22 22 14 42

   * - Parameter
     - Type
     - Default
     - Meaning
   * - ``axis``
     - ``Axis | str``
     - required
     - World axis to align along. One of ``x``, ``y``, ``z``.
   * - ``offset_m``
     - ``float``
     - ``0.0``
     - Signed subject-minus-reference centre displacement along that axis.
   * - ``tolerance_m``
     - ``float``
     - ``0.02``
     - Zero-penalty alignment band and maximum error accepted by placement validation.
   * - ``relation_loss_weight``
     - ``float``
     - ``1.0``
     - Weight of the alignment objective during solving.

YAML:

.. code-block:: yaml

   relations:
     - kind: align_with
       subject: <object>
       reference: <object>
       params:
         axis: <x|y|z>

``at_position`` (AtPosition)

.. _relation-clutter_on:

``clutter_on`` (ClutterOn)
--------------------------

Releases the subject above a support, inside a central release region, for physics to settle.

Defines a release pose before physics, not a resting pose. The release region is the central
``spread`` fraction of the support's width and depth, and follows the support if the solver moves
it. The subject's bottom must clear the support by ``clearance_m``; there is no upper height
limit. The support may be an anchor or positioned through its own relations.

**Validation:** the ``clutter_on_relation`` check rejects layouts whose footprint leaves the release
region or whose bottom is below the minimum clearance. It does not check the settled pile.

**Restrictions:** ClutterOn must be the subject's only spatial relation. The support must take part
in placement, cannot itself use ClutterOn, and must stay upright at a fixed yaw that is a multiple
of 90 degrees; a movable support cannot use FaceTo. Roll or pitch on the subject requires
``collision_mode="bbox"``. Not offered to agentic environment generation.

.. list-table::
   :header-rows: 1
   :widths: 22 22 14 42

   * - Parameter
     - Type
     - Default
     - Meaning
   * - ``spread``
     - ``float``
     - ``0.2``
     - Fraction of support width and depth available for release, centered on the support. For example, 0.2 restricts each axis to its central 20%; settled objects may use the full support.
   * - ``clearance_m``
     - ``float``
     - ``0.01``
     - Release clearance above the support in metres.
   * - ``gap_m``
     - ``float``
     - ``0.03``
     - Initial clearance from neighboring release bounds in metres, at least the solver clearance.
   * - ``random_yaw``
     - ``bool``
     - ``True``
     - Sample world-Z yaw in addition to RotateAroundSolution.
   * - ``edge_margin_m``
     - ``float``
     - ``0.0``
     - Inward margin within the release region in metres.
   * - ``relation_loss_weight``
     - ``float``
     - ``1.0``
     - Weight for the relation loss.

YAML:

.. code-block:: yaml

   relations:
     - kind: clutter_on
       subject: <object>
       reference: <object>


.. _relation-face_to:

``face_to`` (FaceTo)
--------------------

Turns the subject so its local +X axis points at the reference in world XY.

Sets the heading only; it does not constrain either object's position. The heading is computed
after positions are solved, from the subject's position towards the reference's, and replaces
any random yaw from ``random_yaw_init``.

**Validation:** the ``face_to`` check rejects layouts where the subject and reference share an XY
position, so that no facing direction is defined.

**Restrictions:** a subject can have only one FaceTo and cannot combine it with
RotateAroundSolution. An anchor cannot use FaceTo, and the reference must take part in placement.
The turn is about the subject's origin, so if the subject's placement bounds are not centred on
its origin, such as a robot on an offset stand, the turn moves the bounds' centre. A horizontal
AlignWith that uses those bounds, as subject or reference, would then no longer hold, so
placement raises an error for that combination. Use a fixed RotateAroundSolution heading or
centred placement bounds instead.

Takes no parameters.

YAML:

.. code-block:: yaml

   relations:
     - kind: face_to
       subject: <object>
       reference: <object>


.. _relation-is_anchor:

``is_anchor`` (IsAnchor)
------------------------

Marks the subject as a fixed reference that the solver does not move.

An anchor keeps its initial pose, which must be set before placement; in a graph YAML an omitted
pose defaults to identity, and an ObjectReference takes its pose from the referenced prim. Several
objects can be anchors. Anchoring does not make an object static or kinematic in physics.

**Validation:** none; anchors are not moved.

**Restrictions:** an anchor's root rotation must be a multiple of 90 degrees about world Z, with no
tilt.

Takes no parameters.

YAML:

.. code-block:: yaml

   relations:
     - kind: is_anchor
       subject: <object>

Python:

.. code-block:: python

   table.set_initial_pose(Pose(position_xyz=(1.0, 0.0, 0.0), ...))
   table.add_relation(IsAnchor())  # Mark as anchor

   chair.set_initial_pose(Pose(position_xyz=(2.0, 0.0, 0.0), ...))
   chair.add_relation(IsAnchor())  # Another anchor

   mug.add_relation(On(table))
   bin.add_relation(NextTo(chair, side=Side.POSITIVE_X))


.. _relation-next_to:

``next_to`` (NextTo)
--------------------

Places the subject beside the reference on one side, with a set gap between their placement boxes.

``side`` picks the reference's side. The gap between the reference's edge on that side and the
subject's facing edge targets ``distance_m``. Along the other horizontal axis the subject may sit
anywhere within the reference's extent, unless ``cross_position_ratio`` sets a soft preference.
The solver treats any gap within ``tolerance_m`` of ``distance_m`` as satisfied, and the default
initializer starts the subject on the requested side within ``tolerance_m``.

**Validation:** the ``next_to`` check rejects layouts where the subject is on the wrong side, or its
gap differs from ``distance_m`` by more than ``tolerance_m``, including when it is closer than
requested. ``cross_position_ratio`` is not checked.

.. list-table::
   :header-rows: 1
   :widths: 22 22 14 42

   * - Parameter
     - Type
     - Default
     - Meaning
   * - ``side``
     - ``Side | str``
     - required
     - Side of the parent, in world axes, to place this object on. One of ``positive_x``, ``negative_x``, ``positive_y``, ``negative_y``.
   * - ``relation_loss_weight``
     - ``float``
     - ``1.0``
     - Weight for the relationship loss function.
   * - ``distance_m``
     - ``float``
     - ``0.05``
     - Target gap in metres between the parent's edge and this object's facing edge.
   * - ``cross_position_ratio``
     - ``float | None``
     - ``None``
     - Soft preference for where to place this object along the parent's other horizontal axis (Y for an X side, X for a Y side), from -1.0 (min edge) through 0.0 (centred) to 1.0 (max edge). None allows any position within the parent's extent.
   * - ``tolerance_m``
     - ``float``
     - ``0.01``
     - Allowed gap error in metres. The solver treats any gap within this value of distance_m as satisfied, and validation passes when the side and gap errors are each within it.

YAML:

.. code-block:: yaml

   relations:
     - kind: next_to
       subject: <object>
       reference: <object>
       params:
         side: <positive_x|negative_x|positive_y|negative_y>


.. _relation-not_next_to:

``not_next_to`` (NotNextTo)
---------------------------

Keeps the subject out of the region beside the reference on one side.

The inverse of NextTo. The keep-out region starts at the reference's edge on ``side``, extends
outward without limit, and spans the reference's footprint along the other horizontal axis: for
``side=positive_y``, everything past the reference's +Y edge within its X extent. Positions off
either end of that footprint stay free at any distance. The subject must clear the region by a
margin, 0.1 m by default, set by ``NotNextToLossStrategy.margin_m`` in
``RelationSolverParams.strategies``.

**Validation:** the ``not_next_to`` check rejects layouts where the subject has not cleared the
keep-out region, to within ``tolerance_m``.

.. list-table::
   :header-rows: 1
   :widths: 22 22 14 42

   * - Parameter
     - Type
     - Default
     - Meaning
   * - ``relation_loss_weight``
     - ``float``
     - ``1.0``
     - Weight for the relationship loss function.
   * - ``side``
     - ``Side | str``
     - ``'positive_x'``
     - Side of the parent, in world axes, that is blocked. One of ``positive_x``, ``negative_x``, ``positive_y``, ``negative_y``.
   * - ``tolerance_m``
     - ``float``
     - ``0.01``
     - Slack (meters) for placement validation: the child passes when it has cleared the keep-out zone to within this value.

YAML:

.. code-block:: yaml

   relations:
     - kind: not_next_to
       subject: <object>
       reference: <object>


.. _relation-on:

``on`` (On)
-----------

Places the subject on top of the reference, with its footprint inside the reference's top surface.

Uses the top and XY footprint of the reference's axis-aligned placement box, inset by
``edge_margin_m`` so the subject stays off the rim. With ``overlap=True`` the footprints only need
to overlap on both horizontal axes and the margin is ignored; the subject may then tip or fall.
For L-shaped, hollow or concave supports, anchor an ObjectReference to the actual support surface.

**Validation:** the ``on_relation`` check rejects layouts where the subject's bottom is not within
``clearance_m`` above the reference's top, give or take ``ObjectPlacerParams.on_relation_z_tolerance_m``,
or where its footprint leaves the inset support (or, with ``overlap=True``, does not overlap it).

.. list-table::
   :header-rows: 1
   :widths: 22 22 14 42

   * - Parameter
     - Type
     - Default
     - Meaning
   * - ``relation_loss_weight``
     - ``float``
     - ``1.0``
     - Weight for the relationship loss function.
   * - ``clearance_m``
     - ``float``
     - ``0.01``
     - Allowed gap in metres between the parent's top and this object's bottom.
   * - ``edge_margin_m``
     - ``float``
     - ``0.05``
     - Inward inset in metres from each X/Y edge of the parent's surface, applied only for containment. Ignored when overlap is True.
   * - ``overlap``
     - ``bool``
     - ``False``
     - Require only footprint overlap on both X and Y instead of full containment.

YAML:

.. code-block:: yaml

   relations:
     - kind: 'on'
       subject: <object>
       reference: <object>

``position_limits_box`` (PositionLimitsBox)
-------------------------------------------

Keeps the subject's position within an axis-aligned box in world coordinates.

Give each axis as a (minimum, maximum) pair; None leaves that bound open, and omitted axes are
free.

**Validation:** none; this is a solver objective only, so a valid layout can exceed the limits
slightly.

**Also accepted as:** ``position_limits``

.. list-table::
   :header-rows: 1
   :widths: 22 22 14 42

   * - Parameter
     - Type
     - Default
     - Meaning
   * - ``x_limits``
     - ``Sequence[float | None]``
     - ``(None, None)``
     - Minimum and maximum world X in metres; None leaves a bound open.
   * - ``y_limits``
     - ``Sequence[float | None]``
     - ``(None, None)``
     - Minimum and maximum world Y in metres; None leaves a bound open.
   * - ``z_limits``
     - ``Sequence[float | None]``
     - ``(None, None)``
     - Minimum and maximum world Z in metres; None leaves a bound open.
   * - ``relation_loss_weight``
     - ``float``
     - ``1.0``
     - Weight for the relationship loss function.

YAML:

.. code-block:: yaml

     - kind: position_limits_box
       subject: <object>

Python:

.. code-block:: python

``position_limits_cylindrical`` (PositionLimitsCylindrical)
-----------------------------------------------------------

Keeps the subject's world-XY distance from a fixed centre within a radius range.

``radius_min`` alone keeps the subject outside a cylinder, ``radius_max`` alone keeps it inside
one, and both give an annulus. It does not constrain Z; use PositionLimitsBox for that or for
axis-aligned XY limits.

**Validation:** none; this is a solver objective only, so a valid layout can exceed the limits
slightly.

.. list-table::
   :header-rows: 1
   :widths: 22 22 14 42

   * - Parameter
     - Type
     - Default
     - Meaning
   * - ``center_x``
     - ``float``
     - required
     - World X of the cylinder's axis in metres.
   * - ``center_y``
     - ``float``
     - required
     - World Y of the cylinder's axis in metres.
   * - ``radius_min``
     - ``float | None``
     - ``None``
     - Smallest allowed XY distance from the centre in metres, or None for no minimum.
   * - ``radius_max``
     - ``float | None``
     - ``None``
     - Largest allowed XY distance from the centre in metres, or None for no maximum.
   * - ``relation_loss_weight``
     - ``float``
     - ``1.0``
     - Weight for the relationship loss function.

.. code-block:: yaml

   relations:

.. _relation-requires_reachability:

``requires_reachability`` (RequiresReachability)
------------------------------------------------

Requires the robot to reach a top-down grasp at the subject.

Adds no solver objective; it only rejects layouts. Tasks such as pick and place add it to the
objects they need the robot to grasp.

**Validation:** the ``ik_reachable`` check solves cuRobo IK for a top-down grasp at the subject from
the robot's placed base, and rejects layouts where it fails. The check runs only when
``ObjectPlacerParams.reachability_config.embodiment`` has a cuRobo configuration.

Takes no parameters.

YAML:

.. code-block:: yaml

   relations:
     - kind: requires_reachability
       subject: <object>

Python:

.. code-block:: python

   banana.add_relation(RequiresReachability())  # IK-check reachability of the banana


.. _relation-rotate_around_solution:

``rotate_around_solution`` (RotateAroundSolution)
-------------------------------------------------

Applies a fixed rotation to the subject on top of its solved position.

The solver does not optimise it; placement composes this rotation with the solved position. Use
it for a fixed heading, such as a robot facing a counter. Because the heading is known before
solving, it works with AlignWith on objects whose placement bounds are off-centre, unlike FaceTo.
A ClutterOn subject keeps it as its base rotation.

**Validation:** none.

**Restrictions:** cannot be combined with FaceTo on the same subject.

.. list-table::
   :header-rows: 1
   :widths: 22 22 14 42

   * - Parameter
     - Type
     - Default
     - Meaning
   * - ``roll_rad``
     - ``float``
     - ``0.0``
     - Roll rotation in radians.
   * - ``pitch_rad``
     - ``float``
     - ``0.0``
     - Pitch rotation in radians.
   * - ``yaw_rad``
     - ``float``
     - ``0.0``
     - Yaw rotation in radians.

YAML:

.. code-block:: yaml

   relations:
     - kind: rotate_around_solution
       subject: <object>

Python:

.. code-block:: python

   import math
   box.add_relation(On(desk))
   box.add_relation(RotateAroundSolution(yaw_rad=math.pi / 4))
   # -> ObjectPlacer sets a Pose with solved position and 45° yaw rotation
