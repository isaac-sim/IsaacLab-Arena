Placement Validation
====================

Validators evaluate solved layouts before Arena applies them.

Validation Stages
-----------------

Arena can check placement at three stages:

1. **Geometric validation during placement** checks collisions and whether
   relations such as ``On``, ``NextTo``, and ``FaceTo`` are satisfied.
2. **Task-aware validation during placement** can reject layouts whose task
   targets are unreachable. When the cuRobo extension and a compatible
   embodiment configuration are available, the ``ik_reachable`` check runs
   only after the required inexpensive checks pass. It currently evaluates
   reachability from the embodiment's configured initial base pose, not a base
   pose generated by placement relations.
3. **Physics validation** can test whether a completed layout remains stable
   after simulation starts.

These stages are distinct because a geometrically valid object can still topple
or slide under physics, and geometric proximity alone does not guarantee that a
robot can reach a task target.

cuRobo Reachability
-------------------

``RequiresReachability`` identifies the objects that the IK check evaluates:

.. code-block:: python

   from isaaclab_arena.relations.relations import RequiresReachability

   target_object.add_relation(RequiresReachability())

If the check finds no marked targets, it prints a warning and passes every
layout without running IK.

Choosing Validation Checks
--------------------------

By default, every available build-time check runs and is required for a layout
to count as valid. Environment graph specifications can select a subset:

.. code-block:: yaml

   placement_validators:
     enabled_checks:
       - no_overlap
       - on_relation
       - next_to
     required_checks:
       - no_overlap
       - on_relation

Built-in geometric check names are ``no_overlap``, ``on_relation``,
``next_to``, ``not_next_to``, and ``face_to``. Extension packages may register
additional checks such as ``ik_reachable``. Every required check must also be
enabled. A check is enforced only when its validator is registered and
available; listing an unavailable check does not enable it.

Physics Stability
-----------------

Run the optional physics check on a registered environment with:

.. code-block:: bash

   python isaaclab_arena/scripts/run_placement_pool_validation.py \
     --viz none \
     --num_envs 4 \
     pick_and_place_maple_table

``--viz none`` disables visualizers so the validation sweep runs
noninteractively.

When Placement Fails
--------------------

Check the intent before tuning solver parameters:

1. Confirm that the requested relations are compatible.
2. Check that anchors and support surfaces have the expected poses and bounds.
3. Check whether a bounding box is rejecting otherwise valid free space.
4. Inspect physics behavior if geometry passes but objects move or topple.

Only after identifying the failure should you adjust clearances, collision
mode, placement attempts, or solver settings. If fallback layouts are enabled
and no candidate passes every required check, Arena prints
``Falling back to best-loss layouts for envs: ...`` and may retain the
highest-ranked layouts even though some checks failed. Set
``ObjectPlacerParams.allow_best_loss_fallbacks=False`` when every applied layout
must pass; if no valid layout can be produced, construction or pool refill
raises ``RuntimeError``.
