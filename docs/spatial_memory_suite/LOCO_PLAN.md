# G1 loco-manipulation task plan

Tasks 1–3 completed the pilot. Tasks 4–30 are proposed experiments. Each uses the head camera, a physically grasped box, and the existing G1 walking and squeeze postures. A shelf reach means walking up to a shallow opening at the demonstrated hand height. Reach depth, clearance and stable release need measurement.

## Trial design

For each row, generate four equally likely answers by permuting the relevant geometry independently of starting pose. Jitter start position, approach distance and fixture positions within physically reachable bounds. Use the same distribution for both controllers. Where the answer is a continuous location, sample four separated feasible regions with disjoint success tolerances. The blind strategy follows the same inspection and handling motions and commits to a fixed feasible answer. Its expected success is at most one in four **if** the current view, instruction and proprioception contain no answer. Compare matched episodes with different correct answers at the same decision pose, including recent frames, to check that assumption.

The inspection must expose enough geometry to distinguish all four answers. Track the actual discriminating surfaces as remembered targets. Return to a common decision pose after inspection to prevent the final inspection pose from encoding the answer. Reveal the query only after the targets have been hidden longer than the three-second history. Latch the first physical commitment (a crossed boundary, grasp or placement, as specified below). Fail a wrong first commitment even if later corrected. Count rediscovery before commitment as failure. Require physical manipulation and the correct final object pose for success.

## Proposed retrieval and exit tasks

Every trip ends with the G1 carrying the carton out and releasing it upright at the receiving station. All fixtures stay fixed. The common pickup pose separates inspection from the loaded decision. Each row identifies the physical action that commits the robot and the layout feature the oracle uses. A blind controller can perform the same pickup and manage visible obstacles. Its unknown is the row-specific exit geometry.

## Evidence required before accepting a new task

1. **Build matched counterexamples.** For each task, construct four layouts with the same inbound actions, pickup pose, query, carton, visible local geometry and recent head-camera history at the decision. Change only the previously observed exit geometry. Include start and fixture jitter independently of the answer. Record the correct commitment and show that the sets of collision-free successful commitments do not overlap. For two-stage binary tasks, check this at each stage. The 25% chance bound depends on equally likely alternatives and indistinguishable observations.
2. **Try to defeat the design.** Run the fixed-choice blind controller, a current-view controller that can steer and follow a wall, and a controller that reverses the inbound motion using odometry. Also test the three-second frame history. Allow looking around and inexpensive recovery in a diagnostic run with the search penalty disabled. If a controller can reliably exit by peeking, probing, reversing the path or moving slowly along a wall, revise the geometry or record the task only as a test of avoiding repeated search.
3. **Test what the map contributes.** Give the same controller an occupancy map built from the inbound head-camera observations, then erase or swap the hidden part of that map at pickup while preserving pose, instruction and visible obstacles. Compare completion, first choice and first contact on matched seeds. The privileged layout oracle establishes physical feasibility. A successful map-assisted controller and a drop under map removal provide separate evidence for the value of reconstruction. A policy can also retain sufficient spatial information internally or as a compact route description.
4. **Apply the pilot thresholds.** Require at least 45/50 privileged oracle successes and at most 15/50 successes for each tested memoryless baseline. Keep deterministic reset, all four observation variants and per-episode records. Check earlier visibility, the history-length delay and every claimed hidden phase in solved episodes. Cross-check new occlusion mechanisms against rendered instance masks. Record paired head-camera videos through pickup, commitment and release.
5. **Measure feasibility first.** Use the existing whole-body controller, two-hand squeeze grasp, shallow reachable supports and static fixtures. Measure unloaded and loaded swept volumes before setting clearances. Check scene spacing, walking time and grasp reliability. A lane that the oracle cannot traverse reliably is a failed design even if all blind policies collide.

Start with 4, 5 and 20. They isolate longitudinal clearance, loaded turning space and integration of two partial views. Their failures can be diagnosed separately before combining mechanisms in task 30.
