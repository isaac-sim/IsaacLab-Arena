# Deformable Framework Support Motivation, Goals, and Design

DRAFT, UNDER REVIEW

# Motivation

Isaac Lab already supports `DeformableObjectCfg`, but Arena's scene, asset, and task APIs assume rigid bodies. Customers want to benchmark models on deformables.

Deformable support should preserve Arena's compositional model: register a Newton/PhysX-ready deformable USD as an Arena asset → compose with embodiment \+ task → select a compatible physics preset → run existing policy evaluation.

A new Arena DeformableObject class alone is insufficient. Tasks and predicates make implicit rigid-body assumptions (e.g. pick-and-place success via contact sensing and root velocity). With deformables, task should return type-aware predicates, and existing predicates should be updated to work with deformables using nodal state.

# Goals

- **New Deformable Object Class:** Arena `DeformableObject` with volume and surface deformable material.
- **Support multi-backend:** One Arena `DeformableObject` → PhysX or Newton `DeformableObjectCfg` from the selected preset. `ArenaEnvBuilder` resolves physics backend/solver presets, validates asset/task compatibility.
- **Task requirements:** Task declares required object type. `make_termination_cfg` picks object-type-aware default predicates.
- **Capability-checked predicates:** Assets declare capabilities; predicates declare needs; `ArenaEnvBuilder` validates the task assets / success predicates compatibility.
- **Placement:** Deformables offer rest-shape `get_bounding_box` and apply reset pose over default nodal state. Placement solver stays object-type-agnostic.
- **Examples:** (1) DROID deformable pick-and-place (swappable volume/cloth/cable pick). (2) A new cable-routing task.

# Non-Goals

- Migrate existing rigid examples to Newton.
- Author or tune Newton assets (use Lab-validated USD/spawners only).
- Tasks beyond the two examples (no cloth folding / bag handling).
- Make every predicate deformable-safe (rigid-only predicates using contact sensor stay).
- Train deformable policies (evaluate with Pi / OSMO; no Arena checkpoints).
- Support every Lab soft backend/solver (subset of 3.0 GA is enough).

# High-Level API

Arena DeformableObject using a `usd_path` or Lab mesh `spawner_cfg`. `VolumeDeformableMaterial/SurfaceDeformableMaterial` is set per-object and overwrites USD default following Lab’s pattern.
Placement bbox is auto-computed (USD via `compute_local_bounding_box_from_usd`, spawners from `size`).

```py
# From USD (volume or surface rest mesh)
soft_cube = DeformableObject(
    name="soft_cube",
    usd_path="/path/to/soft_cube.usd",
    material=VolumeDeformableMaterial(youngs_modulus=8e4, poissons_ratio=0.4, density=300),
)

# From Lab spawner — volume (soft cube / beam)
soft_beam = DeformableObject(
    name="soft_beam",
    spawner_cfg=sim_utils.MeshCuboidCfg(size=(0.3, 0.04, 0.04), edge_refinement=3.0),
    material=VolumeDeformableMaterial(youngs_modulus=2e5, poissons_ratio=0.3, density=1000),
)

# From Lab spawner — surface (cloth)
cloth = DeformableObject(
    name="cloth",
    spawner_cfg=sim_utils.MeshRectangleCfg(size=(0.2, 0.2), resolution=(8, 8)),
    material=SurfaceDeformableMaterial(
        density=1.0, thickness=0.001, stretch_stiffness=5e2, bend_stiffness=0.5,
    ),
)

environment = IsaacLabArenaEnvironment(
    name="droid_deformable_cube_pick_and_place",
    embodiment=DroidAbsoluteJointPositionEmbodiment(enable_cameras=True),
    scene=Scene(assets=[soft_cube, destination, table]),
    task=PickAndPlaceTask(pick_up_object=soft_cube, destination=destination),
    default_physics_preset="newton_mjwarp_vbd",
)
```

```shell
python isaaclab_arena/evaluation/policy_runner.py \
    --presets newton_mjwarp_vbd \
    --enable_cameras \
    droid_deformable_cube_pick_and_place
```

Incompatible task / asset / preset → fail at ArenaEnvBuilder.

## Predicates and runtime state access

Predicates use a proposed Arena state adapter rather than reaching directly into Lab rigid or deformable buffers. Arena adds `object_state` over Lab's asset-specific data buffers to provide a uniform state view:

```py
state = object_state(env, object_cfg.name)
position_w = state.aggregate.position_w          # [num_envs, 3]
linear_velocity_w = state.aggregate.linear_velocity_w
if state.points is not None:                      # deformable only
    points_w = state.points.position_w            # [num_envs, num_nodes, 3]
    point_velocity_w = state.points.linear_velocity_w
```

The API unifies field names, not every object capability. Missing state is `None`: rigid objects have no point state, while deformables have no aggregate or point orientation/angular velocity. Builder capability validation catches incompatible task/object combinations before runtime.

The initial predicate changes are:

- **New:** deformable `object_supported_by(...)` using `state.points.position_w` plus the destination's existing bounds/collision representation.
- **Generalized:** `objects_settled(...)` using deformable point velocity or rigid aggregate linear/angular velocity; height predicates using `centroid | min | max`; `objects_in_proximity(...)` using aggregate position.
- **Retained as rigid-only:** contact-based `object_on_destination(...)`, with declared `CONTACT_SENSOR` and velocity requirements.

# What are we missing to achieve this?

## 1\. New DeformableObject And ObjectBase Refactoring

Add `ObjectType.DEFORMABLE` and `DeformableObject` as an `ObjectBase` subclass. Share placement/catalog; keep nodal config/reset off rigid/articulation paths.

Declares: USD or Lab spawner; volume vs surface; `VolumeDeformableMaterial` / `SurfaceDeformableMaterial`

Refactor: strip rigid-root assumptions from `ObjectBase`; keep rigid/static/articulation on `Object`; leave `ObjectReference` separate.

## 2\. VolumeDeformableMaterial / SurfaceDeformableMaterial

Lab has **backend- and kind-specific** material cfgs — not a single portable type. Volume and surface differ in fields; PhysX vs Newton differ further.

**Volume** (soft beam / teddy):

```py
# PhysX — PhysxDeformableBodyMaterialCfg
PhysxDeformableBodyMaterialCfg(
    density=1000.0, youngs_modulus=..., poissons_ratio=...,
    static_friction=10.0, dynamic_friction=10.0,
)
# Newton — NewtonDeformableBodyMaterialCfg (Young’s/Poisson → Lamé)
NewtonDeformableBodyMaterialCfg(
    density=1000.0, particle_radius=0.0025,
    k_mu=..., k_lambda=..., k_damp=0.0,
)
```

**Surface** (cloth):

```py
# PhysX — PhysxSurfaceDeformableBodyMaterialCfg
PhysxSurfaceDeformableBodyMaterialCfg(
    density=1000.0, youngs_modulus=1e6, poissons_ratio=0.25,
    surface_thickness=0.001, surface_bend_stiffness=1e6,
    elasticity_damping=0.1, bend_damping=0.1, ...
)
# Newton — NewtonSurfaceDeformableBodyMaterialCfg (no Young’s/Poisson)
NewtonSurfaceDeformableBodyMaterialCfg(
    density=1.0, particle_radius=0.002,
    tri_ke=5e2, tri_ka=5e2, tri_kd=1e-3, edge_ke=0.5, edge_kd=1e-3,
)
```

**Arena proposal:** two backend-neutral (volume / surface) types. `resolve_object_cfg` maps them onto the Lab cfgs above.

```py
# volume → PhysX Young’s/Poisson or Newton Lamé (+ particle_radius)
VolumeDeformableMaterial(youngs_modulus=2e5, poissons_ratio=0.3, density=1000)

# surface → PhysX surface_* or Newton tri_*/edge_*
SurfaceDeformableMaterial(
    density=1.0, thickness=0.001, stretch_stiffness=5e2, bend_stiffness=0.5, ...
)
```

## 3\. Physics Presets

| Layer | Owns |
| :---- | :---- |
| **Asset** | Requirements; backend-neutral source \+ `VolumeDeformableMaterial` / `SurfaceDeformableMaterial` |
| **Preset registry** | Backend, solver cfg, `replicate_physics`, supported deformable kinds |
| **Environment** | `default_physics_preset`; optional typed overlay |
| **ArenaEnvBuilder** | Resolve → overlay → validate → `resolve_object_cfg` |

```py
preset = physics_presets.resolve(requested_preset, environment, scene_requirements)
name, object_cfg = asset.resolve_object_cfg(preset.physics_context)
```

Rigid/articulated/static: keep today’s `get_object_cfg()`.
Deformable: `VolumeDeformableMaterial` / `SurfaceDeformableMaterial` → backend Lab material cfgs. Global VBD stays on the **preset**, not the object.

### Per-env solver overlay

Lab soft tasks need different VBD/substep/contact knobs (soft vs cloth vs cable). Today `--presets` runs **after** `env_cfg_callback` and replaces `sim.physics`, so callback tuning is discarded.

**Rule:** named registry presets for reusable stacks; optional allowlisted overlay after preset apply. Do not use `env_cfg_callback` for deformable physics.

```
resolve preset (--presets > env.default > requirement-derived > rigid default)
  → apply preset (physics + replicate_physics)
  → apply physics_overlay (allowlisted fields only)
  → env_cfg_callback (non-physics: teleop, cameras, …)
  → assets.resolve_object_cfg(...)
```

```py
environment = IsaacLabArenaEnvironment(
    ...,
    default_physics_preset="newton_mjwarp_vbd",
    physics_overlay=PhysicsOverlay(num_substeps=4, vbd_iterations=5),  # optional
)
```

Shareable stacks (cloth vs volume vs cable) → new preset. Overlay → small local deltas only.

## 4\. Explicit task object requirements

`make_termination_cfg` selects defaults by `object_type`.

```py
def make_termination_cfg(self):
    if self.pick_up_object.object_type == ObjectType.DEFORMABLE:
        predicates = [object_supported_by, ...]
    elif self.pick_up_object.object_type == ObjectType.RIGID:
        predicates = [object_on_destination, ...]
    else:
        raise ValueError(...)
    if self.max_separation is not None:
        predicates.append(objects_in_proximity)
    return TerminationsCfg(
        success=TerminationTermCfg(
            func=check_success,
            params={"mode": SuccessMode.ALL, "predicates": predicates},
        ),
        ...
    )
```

## 5\. Deformable-aware success predicates

Assets provide capabilities; predicates declare needs; builder validates.

```py
class ObjectBase(PlaceableAsset, ABC):
    def capabilities(self) -> frozenset[ObjectCapability]: ...
    def supports(self, capability: ObjectCapability) -> bool: ...

class ObjectCapability(StrEnum):
    CONTACT_SENSOR = "contact_sensor"      # rigid; contact success + Mimic
    ORIENTATION = "orientation"            # deformables: none
    LINEAR_VELOCITY = "linear_velocity"    # static: none
    ANGULAR_VELOCITY = "angular_velocity"  # deformables/static: none
    NODAL_STATE = "nodal_state"            # deformable; nodal obs
```

```py
@predicate(requires={"object_cfg": {CONTACT_SENSOR, LINEAR_VELOCITY}})
def object_on_destination(...): ...

@predicate(requires={"object_cfg": {NODAL_STATE}})
def object_supported_by(...): ...

@predicate(requires={"object_cfg": {LINEAR_VELOCITY}},
           requires_if={"require_angular_velocity": {"object_cfg": {ANGULAR_VELOCITY}}})
def objects_settled(..., require_angular_velocity=True): ...
```

New / generalized:

- `objects_in_proximity`: compare `aggregate.position_w`.
- Height predicates: reduce deformable `points.position_w[..., 2]` with `mean | amin | amax`; retain rigid root-height behavior.
- `objects_settled`: use maximum deformable point speed; use rigid aggregate linear/angular speed.
- `object_supported_by`: select the deformable's low nodal points and compare them with the destination's existing transformed bounds/collision surface.

## 6\. Runtime State Access

Avoid branching on Lab types × backends throughout Arena. `object_state` / `ObjectState` are proposed Arena APIs: thin, read-only adapters over state buffers already supplied by Isaac Lab.

```py
state = object_state(env, name)
aggregate = state.aggregate  # one object-level state per environment
points = state.points        # deformable nodal state, otherwise None
```

Both PhysX and Newton deformables expose `data.nodal_pos_w`, `data.nodal_vel_w`, `data.root_pos_w`, and `data.root_vel_w`. Lab computes `root_pos_w` and `root_vel_w` lazily as the arithmetic mean of the simulation-node positions and velocities. Rigid objects expose root pose and root linear/angular velocity.

`KinematicState` is a new Arena value type, not an existing Isaac Lab API:

```py
@dataclass(frozen=True)
class KinematicState:
    position_w: torch.Tensor | None = None
    orientation_w: torch.Tensor | None = None
    linear_velocity_w: torch.Tensor | None = None
    angular_velocity_w: torch.Tensor | None = None


@dataclass(frozen=True)
class ObjectState:
    aggregate: KinematicState
    points: KinematicState | None = None


def object_state(env, name: str) -> ObjectState:
    # Dispatch from the Arena ObjectType selected during composition.
    # Do not probe Lab buffers with hasattr or branch on the physics backend.
    ...
```

The adapter dispatches explicitly from Arena `ObjectType`; backend-specific buffer mapping is contained in the adapter. It does not pack fields into a single `[..., state_dim]` tensor.

| Object kind | `aggregate` | `points` |
| :---- | :---- | :---- |
| Rigid | position ← Lab `root_pos_w`; orientation ← `root_quat_w`; linear velocity ← `root_lin_vel_w`; angular velocity ← `root_ang_vel_w` | `None` |
| Deformable | position ← Lab `root_pos_w` (mean nodal position); linear velocity ← `root_vel_w` (mean nodal velocity); orientation/angular velocity `None` | position ← `nodal_pos_w`; linear velocity ← `nodal_vel_w`; orientation/angular velocity `None` |
| Static | position/orientation when available; velocity fields `None` | `None` |

`E` is `num_envs`; deformable aggregate tensors have shape `[E, 3]`, while deformable point position/velocity have shape `[E, N, 3]` for `N` simulation nodes. The nodal mean is a simulation-node centroid, not necessarily a mass-weighted center of mass.

Capability validation should make `None` unexpected on a valid code path. Consumers still assert required fields locally so a composition bug fails clearly.

### Value of the Arena `ObjectState` wrapper

`ObjectState` does not eliminate the semantic differences between rigid and deformable objects. Settling, support, containment, orientation, and other shape-dependent operations remain type/capability-specific. Its value is a narrow, stable Arena boundary:

- **Normalize Lab naming:** rigid linear velocity is `root_lin_vel_w`, while deformable mean nodal velocity is `root_vel_w`; both map to `aggregate.linear_velocity_w`.
- **Normalize backend representation:** contain PhysX/Newton implementation selection and `ProxyArray` → `torch.Tensor` conversion in one place.
- **Share genuinely common fields:** coarse position, proximity, observations, rewards, and translation metrics can read `aggregate.position_w` / `aggregate.linear_velocity_w` without branching.
- **Centralize unavoidable branching:** consumers branch on an Arena capability or `points is not None`, not on Lab classes, physics backends, buffer names, and conversion details.
- **Insulate Arena from Lab API changes:** backend field changes update the adapter rather than every predicate, observation, reward, termination, and metric.

```py
state = object_state(env, name)
if state.points is not None:
    speed = torch.linalg.vector_norm(state.points.linear_velocity_w, dim=-1).amax(dim=1)
else:
    linear_speed = torch.linalg.vector_norm(state.aggregate.linear_velocity_w, dim=-1)
    angular_speed = torch.linalg.vector_norm(state.aggregate.angular_velocity_w, dim=-1)
```

The wrapper promises uniform access only where semantics are shared; it does not fabricate uniform behavior or unavailable fields. If it is adopted by only a few predicates, it is unnecessary abstraction. Its justification depends on migrating the broader Arena consumers below.

### Arena consumers

The following existing rigid-state readers can migrate to `object_state` when their object role accepts `ObjectBase`:

| Consumer | Current rigid access | Unified access / constraint |
| :---- | :---- | :---- |
| `tasks/predicates` | root position and root linear/angular velocity | aggregate state for rigid/coarse checks; deformable point state for settling and height |
| `tasks/observations/observations.py` | object `root_pos_w` | `aggregate.position_w`; preserves coarse centroid semantics |
| `tasks/rewards/rewards.py`, `lift_object_rewards.py` | object root position | `aggregate.position_w` for coarse reach/lift/goal rewards; use points directly only when shape semantics are required |
| `tasks/terminations.py` | object root position/quaternion | aggregate position; orientation-dependent termination remains capability-checked and unavailable to deformables |
| `metrics/object_moved.py` recorder | rigid root-link linear velocity | aggregate linear velocity for translation semantics, or explicit maximum point speed when deformation counts as movement |
| `utils/physics_settle.py` | rigid root linear/angular velocity | same rigid aggregate/deformable maximum-point-speed logic as `objects_settled` |
| `affordances/placeable.py` runtime pose reads | rigid root position/quaternion | aggregate state for reads; writes continue through object-type-specific pose/reset APIs |

Do not migrate robot/articulation-specific embodiment observations, contact-sensor reads, relation solving/rest geometry, or pose/state write paths to this read-only object API.

## 7\. Relation Solver and Placement Validation

Solver is pre-sim and type-agnostic. Deformable \= rest-shape proxy.

```
relations → rest AABB / collision mesh
output    → translation + yaw (undeformed)
reset     → transform default nodal state
```

No sag/drape prediction. Optional post-spawn settle check separately.

```py
def get_bounding_box(self) -> AxisAlignedBoundingBox: ...   # required (rest)
def get_collision_mesh(self) -> trimesh.Trimesh | None: ... # optional; MESH else AABB
# override: set_initial_pose / _build_reset_event (nodal) / layout_pose_to_scene_writes
```

Same `CollisionMode.BBOX | MESH` as rigid. Around the solver only: nodal layout writes; settle validators use max point speed (not rigid root vel).

# Design Decisions and Alternatives

- **Per-preset config bundles vs delayed backend-specific generation** — prefer delayed generation. One backend-neutral source/material; after preset selection, resolve exactly one `DeformableObjectCfg`. Avoids duplicating Newton spawn config across every Newton solver preset.
- **No `StaticObject` / `RigidbodyObject` / `ArticulationObject` split in v0.4** — `DeformableObject` sibling only; keep `Object` \+ `ObjectType` for rigid/static/articulation:
  - USD auto-detect needs a factory before class-per-kind works.
  - Library / env-graph / YAML migration is large and does not unblock deformables.

# Open Questions

- For cable placement, is bbox a good shape to use? It means cable would always spawn in the same shape, is that acceptable?
- Standardize sampled deformable geometry in the episode recorder, or keep task-specific?
